IEEE 802.3 MAC 层学习笔记（阶段一）

2026年06月15日 学习笔记

MAC 层学习记录

参考标准：IEEE Std 802.3-2022（IEEE 802.3-2022）
学习阶段：阶段一 — MAC 公共基础（6/13 – 6/15）

本文记录 Ethernet MAC 子层 公共规范的学习过程，重点覆盖 802.3-2022 Clause 1–4 与 Clause 31（MAC Control）。MAC 负责帧封装/解封装、地址识别、FCS 校验及可选流控；与 PHY 的分界为 MII 家族接口（GMII / XGMII 等）。后续阶段将依次学习 GMII、1000BASE-X PCS 与 10GBASE-R 等速率相关条款。

阅读建议：先通读 Clause 1 的分层图建立全局视角，再按 Clause 2 → 3 → 4 顺序理解「服务接口 → 帧格式 → 操作模型」，最后补充 Clause 31 流控扩展。

802.3 Clause 1：Introduction（概述）

本章说明 Ethernet 范围、分层架构、符号与状态机约定，并在 §1.4 / §1.5 集中给出定义与缩写。

分层架构

整体可分为 传输介质无关层（MAC） 与 传输介质相关层（PHY），分别对应 数据链路层 与 物理层。

架构总图见下图（本阶段重点为 MAC 与 MII 接口一侧）：

子层 / 接口 职责
MAC 帧封装与解析、地址过滤、FCS、流控等
MII 家族 MAC 与 PHY 之间的并行数据接口（GMII、XGMII、XLGMII 等）
PCS 物理编码：编解码、对齐、链路状态
PMA 串并/并串转换、时钟恢复
PMD 将电信号/光信号适配到具体介质（光纤、铜缆、背板等）
MDI 介质相关接口，连接至实际传输介质

双工模式（§1.1.2）

模式 介质使用 冲突处理
半双工 多方共享同一介质 载波侦听 + 冲突检测（CSMA/CD，Clause 4）
全双工 TX/RX 独立通道，不共享介质 无冲突，不使用 CSMA/CD

常见 1G/10G 光纤链路均为全双工；半双工多见于历史百兆共享介质场景。

状态机阅读约定（§1.2.1）

阅读状态机时注意：

  • 同一信号可能被多个状态机引用；
  • 具有全局性质的转换（如从任意状态进入 IDLE 或 RESET）常用 空心箭头 标示；
  • 具体转换条件以标准中的状态转移表为准。

定义与缩写（§1.4 / §1.5）

802.3-2022 将术语与缩写集中在 Clause 1，而非独立成章。阶段一需掌握的核心条目：

缩写 全称 / 含义
MAC Media Access Control，介质访问控制子层
PHY Physical layer device，物理层设备
PCS Physical Coding Sublayer，物理编码子层
PMA Physical Medium Attachment，物理介质附加子层
PMD Physical Medium Dependent，物理介质相关子层
GMII Gigabit Media Independent Interface（1G MAC–PHY 接口，Clause 35）
XGMII 10 Gigabit Media Independent Interface（10G MAC–PHY 接口，Clause 46）
FCS Frame Check Sequence，帧校验序列（CRC-32）
SFD Start Frame Delimiter，帧起始定界符
DA / SA Destination / Source Address，目的 / 源 MAC 地址
MSDU MAC Service Data Unit，MAC 服务数据单元
LLC Logical Link Control（上层 MAC Client，非 MAC 本体）
PAUSE MAC Control 流控帧（Clause 31）
OUI Organizationally Unique Identifier，厂商标识（地址高 24 bit）
I/G Individual/Group bit，地址首字节最低位
U/L Universal/Local bit，地址首字节次低位
Unicast 单播：I/G bit = 0
Multicast 组播：I/G bit = 1，且非全 1
Broadcast 广播：48 bit 地址全为 1（FF:FF:FF:FF:FF:FF）
MA_DATA MAC 子层与 MAC Client 之间的服务原语族（Clause 2）
PLS Physical Layer Signaling，物理层信令（Clause 6–7）

阶段一目标：术语表 ≥ 20 条；上表随学习进度继续扩充。

章节索引用法

后续学习其他速率或 Ethernet 扩展时，可在 Clause 1 按关键词检索，快速定位对应章节。

802.3 Clause 2：MAC service specification（MAC 服务规范）

MAC 通过 服务原语（service primitives） 与上层 MAC Client（如 LLC、桥接逻辑）交互。在 IEEE 802 参考模型中，该接口称为 MSAP。

服务原语概览

原语 方向 作用
MA_DATA.request MAC Client → MAC 请求发送一帧
MA_DATA.indication MAC → MAC Client 指示收到一帧（或接收结果）

MA_DATA.request（发送，§2.3.1）

MAC Client 向 MAC 提交：

参数 说明
destinationAddress 目的 MAC 地址（DA）
sourceAddress 源 MAC 地址（SA）
macServiceDataUnit 待发送 MSDU
frameStatus（发送完成后） 发送结果；若 FCS 由 MAC 计算，则通过状态反映是否出错

MAC 负责 组帧 并经 MII/PLS 向下发送。FCS 由 MAC 本地计算并附加（见 Clause 3.2.9、Clause 4.2.3.1）。

MA_DATA.indication（接收，§2.3.2）

MAC 向 MAC Client 递交：

参数 说明
destinationAddress 解析得到的 DA
sourceAddress 解析得到的 SA
macServiceDataUnit 帧载荷（MSDU）
receptionStatus 接收状态（如 statusOK、frameTooLong、frameCheckError 等）

本质是将 已解析的报文内容 与 本地 MAC 运行结果 一并上送。具体状态枚举见 Clause 4.3.2 与 Clause 4.2.4。

与 Clause 3 的映射

Clause 3.1.2 描述 MSDU 与 MAC 帧字段（DA、SA、Length/Type、Data、Pad、FCS）之间的映射关系。发送时 MAC 将 macServiceDataUnit 嵌入帧体；接收时从已校验帧中提取 MSDU 上送。

数据通路示意

若系统启用 MAC Control，数据帧与控制帧在 MAC Control 层复用后再进入 MAC（见 Clause 31）。

802.3 Clause 3：MAC frame and packet specifications（MAC 帧格式）

帧结构总览（§3.1.1）

各字段说明（§3.2）

字段 标准节 长度 取值 / 规则 作用
Preamble §3.2.1 7 byte 每字节 0x55 时钟同步；直流平衡；提示接收端即将收到帧
SFD §3.2.2 1 byte 0xD5 标识帧起始
DA §3.2.4 6 byte 见下表 目的 MAC 地址
SA §3.2.5 6 byte 须为单播地址 源 MAC 地址
Length/Type §3.2.6 2 byte ≤ 0x0600（1536）为 Length；≥ 0x0601 为 Type（Ethertype） 区分 LLC 长度与上层协议类型

Length / Type 判别示例：

字段值 含义 典型用途
0x005E（94） Length = 94 byte LLC/SNAP 封装，载荷较短
0x0800 Type = IPv4 直接承载 IP 报文
0x0806 Type = ARP 地址解析协议
0x8100 Type = VLAN Tag（802.1Q） 带 Tag 的帧（Q-tag）
0x8808 Type = MAC Control PAUSE / PFC 控制帧
MAC Client Data §3.2.7 0–1500 byte（典型）
Pad §3.2.8 0–N byte
FCS §3.2.9 4 byte
Extension §3.2.10 半双工专用

MAC 地址格式（§3.2.3）

48 bit 地址写作 xx:xx:xx:xx:xx:xx。首字节最低位为 I/G bit，次低位为 U/L bit：

类型 I/G bit（bit 0） 示例
单播（Unicast） 0 00:11:22:33:44:55
组播（Multicast） 1，且非全 1 01:00:5E:xx:xx:xx
广播（Broadcast） 全 6 字节均为 0xFF FF:FF:FF:FF:FF:FF

帧长约束（§3.1.1、Clause 4.4.2）

参数 值 说明
minFrameSize（MAC 帧主体） 64 byte 从 DA 到 FCS；不含 Preamble/SFD
最大帧长（基本 MAC） 1518 byte 含 DA～FCS；不含 Preamble/SFD
最小载荷（Data + Pad） 46 byte Length ≤ 1500 时，不足则由 Pad 填充

FCS（CRC-32，§3.2.9）

  • 生成多项式：0x04C11DB7（反射实现常写作 0xEDB88320）
  • 初始值：0xFFFFFFFF
  • 计算范围：DA 至 Data/Pad 末尾（不含 FCS）
  • 算法：CRC 余数取反后附加在帧尾

比特发送顺序（§3.3）

  • 字节顺序：先传帧中靠前的字节；
  • 字节内比特顺序：低位（LSB）先发。

因此 0x55（01010101）在链路上按 bit 发出为 1,0,1,0,1,0,1,0，按 MSB 重排则呈现为 0xAA。阅读抓包或示波器波形时需与 MII 接口定义区分。

无效 MAC 帧（§3.4）

以下情况可判为无效帧（具体处理见 Clause 4.2.4）：

  • FCS 校验失败；
  • 帧长小于 minFrameSize；
  • Length 字段值与实际情况不符（inRangeLengthError 等）。

TX / RX 职责摘要

方向 MAC 动作（Clause 4 procedural model）
TX 插入 Preamble/SFD，封装 DA/SA/Length/Type/Data/Pad，计算 FCS（§4.2.3.1）
RX 同步帧界，地址识别，FCS 校验，解帧上送 MA_DATA.indication（§4.2.4.1）

实例：最小 IPv4 以太网帧

802.3 Clause 4：Media Access Control（介质访问控制）

本章给出 MAC 功能的精确规范，包括 CSMA/CD、发送/接收过程模型及与相邻层接口。阶段一重点掌握 全双工操作模型、地址识别 与 接收状态枚举；CSMA/CD 半双工细节留待后续按需深入。

操作模型总览（§4.2）

MAC 功能可抽象为 发送实体（Transmit） 与 接收实体（Receive） 两个过程模型，分别响应 MA_DATA.request 与产生 MA_DATA.indication。

发送过程（§4.2.3）

步骤 动作 标准节
1 接收 MA_DATA.request，获取 DA、SA、MSDU §4.2.3.1
2 确定 Length/Type 字段（LLC 长度或 Ethertype） §3.2.6
3 若 Data + Pad 不足 46 byte，插入 Pad §3.2.8
4 计算 FCS（CRC-32，覆盖 DA 至 Pad 末尾） §3.2.9、§4.2.3.1
5 在帧前插入 Preamble（7×0x55）与 SFD（0xD5） §3.2.1–3.2.2
6 经 MII/PLS 逐字节/逐比特送出 §4.2.3.2

全双工发送（§4.2.3.2.6）：TX 与 RX 使用独立通道，无载波侦听、无冲突检测、无退避。MAC 在收到 MA_DATA.request 后即可连续发送，不受对端接收能力以外的介质约束（流控由 Clause 31 PAUSE/PFC 另行处理）。

半双工发送（§4.2.3.2，略读）：共享介质上须执行 CSMA/CD——先侦听信道空闲，发送中持续检测冲突，冲突则中止并按二进制指数退避后重传。现代 1G/10G 链路几乎均为全双工，RTL 实现时可优先实现全双工路径。

接收过程（§4.2.4）

步骤 动作 标准节
1 检测 Preamble/SFD，完成帧同步 §4.2.4.1
2 接收 DA～FCS，实时或整帧校验 FCS §4.2.4.1
3 检查帧长是否满足 minFrameSize / 最大帧长 §4.4.2
4 地址识别：判定本帧是否应递交 MAC Client §4.2.4.1.1
5 组装 MA_DATA.indication，携带 receptionStatus §4.2.4.1、§4.3.2.2

地址识别与过滤（§4.2.4.1.1）

MAC 根据 DA 与本地配置决定 是否将帧上送 MAC Client（frameNotFiltered）或 丢弃（frameFiltered）：

DA 类型 默认行为 可配置项
单播 仅当 DA = 本端口 MAC 地址时接收 Promiscuous mode：接收所有单播
组播 仅当 DA 命中组播过滤表时接收 All multicast：接收所有组播
广播 默认接收（FF:FF:FF:FF:FF:FF） 部分实现允许关闭

实现提示：组播过滤表通常由软件配置 HASH 寄存器或精确匹配表；Promiscuous 模式常用于抓包或桥接场景。被过滤的帧 不产生 MA_DATA.indication，但可计入 frameFiltered 类统计（Clause 5）。

接收状态 receptionStatus（§4.3.2.2）

MA_DATA.indication 中的 receptionStatus 告知 MAC Client 接收结果。常见枚举：

状态 含义 典型触发条件
statusOK 接收成功 FCS 正确、帧长合法、地址未过滤
frameTooLong 帧过长 超过 maxFrameSize（基本 MAC 为 1518 byte，不含 Preamble/SFD）
frameCheckError FCS 错误 CRC 校验失败
alignmentError 对齐错误 帧长非整数字节（半双工场景更常见）
inRangeLengthError Length 字段矛盾 Length ≤ 1500 但 Data 实际长度与 Length 不符
outOfRangeLengthError Length 越界 Length 字段值非法（如 > 1500 却被解析为 Length 而非 Type）

MAC Client 应依据 receptionStatus 决定是否处理 MSDU；仅 statusOK 时载荷可信。错误帧通常只更新 MIB 计数器（Clause 5），不上送上层。

MAC 关键参数（§4.4.2）

参数 典型值 说明
minFrameSize 64 byte DA 至 FCS 的最小长度
maxFrameSize 1518 byte 基本 MAC 最大帧长（不含 Preamble/SFD）
slotTime 512 bit time（64 byte @ 10 Mb/s 基准） 半双工冲突检测窗口；全双工不使用
interFrameGap（IFG） 96 bit time（12 byte @ 10 Mb/s 基准） 帧间最小间隔；各速率按 bit time 缩放
maxFrameDataSize 1500 byte MSDU 最大载荷（不含 Pad）

Jumbo Frame：超出上述基本参数的大帧（如 9000 byte）不属于 IEEE 802.3 基本 MAC 强制范围，需双方协商支持；统计与缓冲设计须单独考虑。

CSMA/CD 概要（§4.1.2，略读存档）

半双工共享介质的核心算法 CSMA/CD（Carrier Sense Multiple Access with Collision Detection）：

  1. 载波侦听（CS）：发送前监听介质，空闲才发送；
  2. 多路访问（MA）：多方共享同一介质；
  3. 冲突检测（CD）：发送过程中若检测到冲突，立即中止并发送 Jam 信号；
  4. 二进制指数退避：冲突后随机等待 $2^n$ 个 slotTime（$n$ 为重传次数，有上限）再重试。

全双工点对点链路不使用 CSMA/CD；学习 PCS/MII 时默认假设全双工即可。

MAC Control / PAUSE / PFC Clause 31 见下文

802.3 Clause 31：MAC Control（媒体访问控制子层扩展）

相关附录：Annex 31A（Opcode 分配）、Annex 31B（PAUSE）、Annex 31D（PFC）
在 IEEE 802 参考模型中，MAC Control 提供可选的 MCSAP（MAC Control Service Access Point）。

MAC Control 位于 MAC Client 与 MAC 之间，负责对普通数据帧与控制帧进行 复用（TX） 与 解复用（RX）：

方向 MAC Control 动作
TX 将 MAC Client 的数据帧与本地产生的 MAC Control 帧合并，统一交给下层 MAC 发送
RX 根据 Length/Type 与 Opcode 判别帧类型：数据帧上送 MAC Client；控制帧在本地处理，通常 不 递交上层，而是触发暂停发送等内部信号

部分控制帧仅在 MAC Control 子层内部”消化”，不向 MAC Client 上送，只产生对应的流控或状态信号。

MAC Control 帧格式（§31.4.1）

MAC Control 帧是特殊的以太网 MAC 帧，Length/Type = 0x8808（MAC Control 类型）：

字段 说明
DA 流控类控制帧使用保留组播地址 01:80:C2:00:00:01（Slow Protocols 组播地址，§31.4.1.1）
SA 发送方 MAC 地址
Length/Type 固定为 0x8808，标识 MAC Control 帧
Opcode 2 字节，指示控制帧类型（Annex 31A）
Parameters 随 Opcode 变化的操作参数（§31.4.1.5）

常见 Opcode

Opcode 名称 附录 作用
0x0001 PAUSE Annex 31B 全链路流控：暂停对端发送普通数据帧
0x0101 PFC（Priority-based Flow Control） Annex 31D 按优先级流控：可单独暂停指定 CoS/优先级队列

PAUSE 帧（Opcode 0x0001）

参数区仅含 2 字节 pause_time：

参数 长度 含义
pause_time 2 byte 暂停时长，单位为 512 bit 时间（bit time quanta）
  • 作用对象：使 接收方 暂停其 TX 方向 上的 普通 MAC 数据帧 发送；
  • 不阻塞 MAC Control 帧本身（控制帧仍可收发）；
  • 效果范围：整条链路 上的数据发送（无优先级区分）。

暂停时间换算：pause_time 单位为 512 bit time。以 1 Gb/s 为例，1 bit time = 1 ns，故：

$$\text{暂停时长 (μs)} = \text{pause_time} \times 512 \times 10^{-3}$$

例如 pause_time = 0xFFFF（65535）时，暂停约 $65535 \times 512 \text{ ns} \approx 33.6 \text{ ms}$。RTL 实现宜在此基础上加上链路传播延迟裕量（aPAUSELinkDelayAllowance）。

PFC 帧（Opcode 0x0101）

参数区结构：

参数 长度 含义
priority_enable_vector 2 byte 位图，指示哪些优先级（0–7）参与本次流控
pause_time[0..7] 8 × 2 byte 每个优先级独立的暂停时间，单位同为 512 bit 时间
  • 与 PAUSE 相同：只暂停对端 TX 方向的 数据帧，不阻塞 MAC Control 帧；
  • 差异：可按 优先级 选择性暂停，未置位的优先级不受影响。

PAUSE 与 PFC 对比

项目 PAUSE PFC
阻塞粒度 全链路数据帧 按优先级（0–7）
参数 1 个 pause_time 1 个 enable 位图 + 8 个 pause_time
典型场景 简单全双工流控 数据中心多队列 / DCB

定时器更新规则（实现要点）

情况 行为
pause_time = 0 解除 暂停（取消当前阻塞）
阻塞尚未结束，又收到新 PAUSE/PFC 以 最新帧 的参数 覆盖 旧值，计时器 重新开始
链路传播延迟 接收方宜将暂停时间 适当加长（pause_time 加上链路延迟裕量），避免对端在旧暂停到期后仍发来数据而造成拥塞

标准在 Annex 31B §31B.3.7 中给出了 PAUSE 定时与链路延迟（aPAUSELinkDelayAllowance）的相关要求；RTL 实现时需预留该裕量。

阶段一知识串联

一句话回顾：MAC Client 通过 MA_DATA 原语与 MAC 交互；MAC 按 Clause 3 格式组帧/解帧，按 Clause 4 执行发送/接收与地址过滤；拥塞时可经 MAC Control 发送 PAUSE/PFC 帧（Clause 31）临时抑制对端数据发送。
