1G/10G 以太网 MAC & PCS 学习与 RTL 实践记录

2026年06月12日 学习计划

关于本系列

本系列记录我从 IEEE 802.3 协议研读到 MAC/PCS RTL IP 交付的全过程，范围聚焦：

纳入 跳过
1G 1000BASE-X（8B/10B、Clause 37 自协商） 1000BASE-T 铜缆 PHY（Clause 35）
10G 10GBASE-R（64B/66B、Clause 73 自协商） RS-FEC / BASE-R FEC（Clause 74、91 等）
GMII / XGMII、MAC 帧格式 10GBASE-T 铜缆自协商（Clause 98 等）

参考标准：IEEE 802.3-2018 或 802.3-2022
时区：全部计划以 北京时间（UTC+8） 为准。

第一阶段逐日任务、产出清单与自测题详见仓库 plan/Plan.md；本文侧重路线图、检查点与阶段交付物，两处内容同步维护。

协议栈速览

802.3 分层（自 MAC 向下）：

1G vs 10G 核心差异（本系列重点）

项目 1G（1000BASE-X） 10G（10GBASE-R）
MAC–PHY 接口 GMII，8 bit 数据 XGMII，32 bit 数据 + 4 bit 控制
PCS 编码 8B/10B（Annex 4A） 64B/66B
带宽效率 ~80% ~97%
自协商 Clause 37（/C/ 有序集） Clause 73（Base Page）
典型串行速率 1.25 Gbps 10.3125 Gbps

项目概述

最终目标：

  1. 完成协议学习与阅读笔记；
  2. 输出 MAC / PCS 的 RTL 整体架构（模块划分、接口定义、结构图与简要文档）；
  3. 完成 RTL 编码与仿真验证；
  4. 在 FPGA 上进行板级验证，并与其他模块联调；
  5. 沉淀 RTL 编写与验证环境，初步完善 RTL IP 库。

自协商要点

主题 1G（Clause 37） 10G（Clause 73）
目的 交换链路能力、完成建链 同上
载体 /C/ 有序集 + Link Code Word Base Page 交换
核心状态 ABILITY_DETECT → ACK_DETECT → COMPLETE 类似框架，字段与超时不同
与 PCS 关系 完成后进入 8B/10B 数据模式 完成后进入 64B/66B 数据模式

明确跳过

条款 原因
Clause 28 100BASE-TX 自协商（选读，不单独排期）
Clause 35 1000BASE-T 铜缆
Clause 74 BASE-R FEC
Clause 91、107、108 等 RS-FEC
Clause 98 等 10GBASE-T 铜缆自协商

学习方法

  1. 先看框图，再看状态机与 TX/RX 细节。
  2. 8 小时日攻坚新内容；3 小时日以复习、自测为主。
  3. Annex 4A 理解原理即可，不必背完整编码表。
  4. 每日收尾 15 分钟更新 checklist，标注疑问点。

阶段检查点

阶段一（6/15 后）

  • 能独立描述 MAC 帧各字段及作用
  • 能解释 MAC 与 PCS 的边界

阶段二（6/22 后）

  • 能画出 1000BASE-X 从 MAC 到 PMA 的数据流
  • 能说明 1G 自协商建链过程

阶段三 / 四（6/30 前）

  • 能对比 GMII 与 XGMII
  • 能解释 64B/66B 块类型
  • 能对比 Clause 37 与 Clause 73 自协商差异

总复习自测题

完成 6/30 前闭卷作答（参考答案计划在笔记整理后另文发布）：

  1. MAC 帧中前导码、SFD、FCS 各占多少字节？作用是什么？
  2. GMII 与 XGMII 的主要区别？
  3. 8B/10B 中 running disparity 是什么？为何需要？
  4. /S/、/T/、/R/ 有序集各出现在帧的什么位置？

  7. 画出 1G 与 10G 从 MAC 到 PCS 的数据流对比图。
  8. Link Code Word 中 Technology Ability 字段的作用？
  9. 自协商 COMPLETE 前经历哪些主要状态？

第二阶段：RTL 架构规划

该阶段核心是规划 MAC 与 PCS 的 RTL 整体结构，划分模块功能与接口。每个模块需交付 结构框图 与 简要设计说明（功能、接口表、状态机概要）。

时间：7/1 – 7/14（北京时间），每天 8 h，共 112 h。
边界：只做架构与文档，不写可综合 RTL，不做仿真。

预期模块划分

实际命名与层级可在 7/1 – 7/3 顶层设计阶段最终确定。

每模块文档模板

每个模块至少包含：

  1. 功能概述（1 段）
  2. 结构框图（含子模块与数据流）
  3. 接口表（信号名、方向、位宽、时钟域、说明）
  4. 状态机概要（若有）
  5. 与 802.3 条款的对应关系

检查点

  • 顶层至子模块层级清晰，命名统一
  • GMII / XGMII / 内部 FIFO 接口定义完整
  • 1G / 10G PCS 复用策略明确（参数化或 generate）
  • 自协商与 PCS 数据模式的切换关系文档化
  • 全部模块均有框图 + 接口表

第三阶段：RTL 编码与仿真验证

时间：7/15 起，具体日程待第二阶段评审后补充。
前提：第二阶段架构文档评审通过。

目标

  • 按架构文档完成 MAC / PCS 可综合 RTL；
  • 搭建 Testbench 与基础验证环境；
  • 通过模块级与顶层仿真（组帧/解帧、编码/解码、自协商建链等场景）。

预期交付物

交付物 说明
RTL 源码 分模块目录，含 README
仿真环境 Testbench、BFM（GMII/XGMII）、波形脚本
仿真报告 用例列表、覆盖要点、已知问题

建议顺序

  1. MAC TX/RX + FCS（不依赖 PCS）
  2. 1G PCS（8B/10B loopback）
  3. 10G PCS（64B/66B loopback）
  4. 自协商 + MAC/PCS 顶层集成仿真

第四阶段：FPGA 板级验证

时间：待定（第三阶段基本通过后启动）。
