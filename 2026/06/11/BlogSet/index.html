Hexo 静态博客搭建指南——从本地到 GitHub Pages

2026年06月11日 建立博客

整体简述

Hexo 是一个快速、简洁且高效的静态博客框架，将 Markdown 文章渲染为静态 HTML 页面。配合 GitHub Pages，可以免费获得一个 https://用户名.github.io 形式的个人网站，无需购买服务器。

本文以 Linux（Debian/Ubuntu 系） 为例，完整走通「注册 GitHub → 本地搭建 Hexo → 配置 SSH 部署 → 公网访问」的流程。

准备过程

1. 注册 GitHub 账号

  1. 打开 GitHub 官网，点击左上角 Sign up 注册。
  2. 填写邮箱（可使用 QQ 邮箱、163 邮箱等）、密码，并完成人机验证。
  3. 注册完成后登录，后续所有仓库与部署操作均在此账号下进行。

2. 创建 GitHub Pages 仓库

  1. 登录后点击右上角 + → New repository。
  2. 仓库名必须为 用户名.github.io（例如用户名为 zhangsan，则仓库名为 zhangsan.github.io）。
  3. 可见性选 Public，其余选项保持默认，点击 Create repository。

注意：仓库名必须严格符合上述格式，否则 GitHub Pages 无法自动识别并发布站点。

配置 SSH 密钥

GitHub 通过 SSH 公钥识别你的身份，切勿将私钥上传或泄露。

1. 生成密钥对

若系统不支持 ed25519，可使用：ssh-keygen -t rsa -b 4096 -C "your_email@example.com"

按提示回车即可使用默认路径 ~/.ssh/id_ed25519（或 id_rsa）。可选设置 passphrase 增加安全性。

2. 将公钥添加到 GitHub

复制输出的整行内容，在 GitHub：头像 → Settings → SSH and GPG keys → New SSH key，Title 随意填写，Key 中粘贴公钥并保存。

3. 测试连接

首次连接输入 yes，若出现 Hi 用户名! You've successfully authenticated... 即表示配置成功。

日常使用流程

步骤 命令 / 操作
写新文章 hexo new "标题" → 编辑 source/_posts/xxx.md
本地预览 hexo clean && hexo g && hexo s
发布上线 hexo clean && hexo g && hexo d
更新主题 进入 themes/主题名 执行 git pull，再重新 generate

建议在项目根目录添加 .gitignore（Hexo 初始化通常已包含），不要把整站源码误推到 用户名.github.io 仓库——该仓库一般只存放 public/ 生成的静态文件；博客源码可另建私有仓库备份。

常见问题

Q：hexo d 报错 Permission denied (publickey)
A：检查 SSH 公钥是否已添加到 GitHub，并执行 ssh -T git@github.com 验证。

Q：网页样式错乱或修改不生效
A：先执行 hexo clean 再 hexo g，浏览器强制刷新（Ctrl+F5）。

Q：GitHub Pages 显示 404
A：确认仓库名为 用户名.github.io、默认分支与 deploy.branch 一致，并等待 Deployments 状态为绿色。

Q：图片无法显示
A：图片应放在 source 下（如 source/images/），Markdown 中引用路径以 / 开头，例如 ![描述](/images/photo.jpg)。

Q：npm 安装慢或失败
A：可切换国内镜像：npm config set registry https://registry.npmmirror.com（仅影响本机 npm，与 Hexo 部署无关）。

总结

通过本文流程，你可以：

  1. 在 Linux 上安装 Node.js 与 Hexo；
  2. 本地初始化博客、更换主题并预览；
  3. 配置 SSH 与 hexo-deployer-git，一键部署到 GitHub Pages；
  4. 通过 hexo new 持续写作并发布。

静态博客的优势在于访问速度快、维护成本低、内容与样式完全自主。后续可按需接入评论（如 Giscus）、统计、搜索插件等，逐步完善个人站点。祝写作愉快。
