千兆以太网 GMII 与 1000BASE-X——从 MAC 原语到线路码组

2026年09月12日 以太网

整体简述

千兆以太网不是把同一套 MAC 直接焊到光模块上，中间隔着一层层双向适配：上层交出报文和链路指令，下层交出码组和线路状态；每一层都既要「装进去」，也要「拆出来」。

本文按 IEEE Std 802.3-2022 整理 1000 Mb/s 这条路径：

  • Clause 34：千兆体系
  • Clause 35：RS 与 GMII
  • Clause 36：1000BASE-X PCS / PMA
  • Clause 37：1000BASE-X 自动协商

管理寄存器见 Clause 22，受管对象见 Clause 30。文中 GMAC/GMII 指千兆媒体独立接口，不是密码学里的 GMAC。状态图与正文冲突时，以状态图为准。

先看分层，再分别写 RS 成帧/解析、PCS 过程与同步、自动协商逻辑。

千兆以太网怎么分层

子层 向上提供什么 向下交付什么
RS 把 GMII 上的帧和指示还原成 MAC 能用的报文与指令 把 MAC 的报文与指令装配成 GMII 帧流
PCS 把线路码组还原成 GMII 字节、错误、载波和配置字 把 GMII 字节与控制编码成连续 10-bit 码组
PMA 对齐后的 10-bit 码组与恢复时钟 1.25 Gb/s 串行比特
自动协商（位于 PCS） 链路能力、Ack、远端故障、xmit 模式 介质上的 /C/ 配置有序集

速率关系：GMII 125 M 八位组/s → PCS 125 M 码组/s → 8B/10B 后线路 1.25 Gb/s。多出的 25% 是线路编码开销。GMII 只定义 1000 Mb/s；10/100 Mb/s 用 Clause 22 的 MII。

千兆相对 100 Mb/s，比特时间按比例缩短。全双工最短包时间约为原来的 1/10；半双工并非按 10 倍缩小，碰撞域里若有两台以上 DTE，必须用中继器组（Clause 41），且 一个碰撞域最多一台中继器。仅全双工的拓扑不允许中继器。

本文 PCS/协商细节针对 1000BASE-X（SX/LX/CX 共用 Clause 36，协商走 Clause 37）。1000BASE-T、T1、KX 分别走 Clause 28、98、73，不要混用。

协调子层 RS：成帧，也解析

RS 做的是 GMII ↔ MAC/PLS 原语 的双向转换，不是单向把引脚翻译给 MAC。

  • 发送（成帧）：收下 MAC 的报文和指令（数据、发送结束、载波延长、错误传播、LPI），按八位组对齐后装配成 GMII 帧流，在 GTX_CLK 域交给 PHY。
  • 接收（解析）：在 RX_CLK 域读 RXD/RX_DV/RX_ER，认出帧界、SFD、延长、假载波、LPI 和帧内错误，把八位组还原成报文，把载波、冲突、数据有效还原成 PLS 指示。

没有发送成帧，MAC 的 request 到不了 PHY；没有接收解析，PHY 的帧也回不成 MAC 的 indication。EEE 时这组映射还会被 LP_IDLE.request/indication 改写。

GMII 本身是 MAC（经 RS）与 PHY 之间的并行数字边界：独立的 8 位收发通路、各自时钟，以及 MDC/MDIO。它屏蔽网线、光模块和编码电平，使同一 MAC 可接不同千兆 PHY。基于 MII，多数信号名沿用，但为 1000 Mb/s 增加了载波延长、LPI、假载波等组合。

发送侧如何把报文打成帧

PLS_DATA.request 的 OUTPUT_UNIT（ONE/ZERO/DATA_COMPLETE/EXTEND/EXTEND_ERROR）每 8 次聚成一拍，和指令一起编码到 TXD[7:0]、TX_EN、TX_ER。

指令/数据 GMII 装配结果
普通报文八位组 TX_EN=1、TX_ER=0，TXD 为该字节；前导码首字节与 TX_EN 同时有效
发送结束 DATA_COMPLETE 最后一个 FCS 字节后、下一 GTX_CLK 上升沿前撤销 TX_EN
载波延长 TX_EN=0、TX_ER=1、TXD=0x0F，必须紧跟在帧数据之后
延长错误 TX_EN=0、TX_ER=1、TXD=0x1F
帧内错误传播 TX_EN=1、TX_ER=1；PHY 在帧中某处发无效码组，字节位置不要求保持
LPI TX_EN=0、TX_ER=1、TXD=0x01
帧间空闲 TX_EN=TX_ER=0；此时 TXD 对 PHY 无影响

整段数据流是：

MAC 给出 7 个前导码 10101010，再加 SFD 10101011（按串行方向书写，每字节 LSB 先出）。TXD[0]/RXD[0] 是 LSB。突发内各帧用载波延长分隔，突发之间才回到真正空闲。

中继器可把输入口解析到的 RX_ER 再编成输出口的 TX_ER，把错误继续向下游成帧。

帧里的 FCS 是什么

<data> 在 GMII 上不是「净荷」两个字，而是 MAC 已经组好的后半段：

FCS（Frame Check Sequence） 由 MAC 按 Clause 3.2.9 计算，不是 RS 或 PCS 生成。它是 4 字节 CRC-32，生成多项式为

$$x^{32}+x^{26}+x^{23}+x^{22}+x^{16}+x^{12}+x^{11}+x^{10}+x^{8}+x^{7}+x^{5}+x^{4}+x^{2}+x+1$$

覆盖范围从 DA 第一比特到数据/填充最后一比特，不含前导码和 SFD。发送时作为 TX_EN=1 期间最后 4 个八位组出现，之后才撤销 TX_EN。

层 对 FCS 做什么
MAC 发送计算并附上；接收用同一算法校验，失败即 FrameCheckError
RS 不计算 FCS。RX_DV 与 RX_ER 同时有效，或收到延长错误时，须保证 MAC 最终校验失败
PCS 把四个字节当成普通 /D/ 编解码。check_end 只是让 MAC 仍能切出「最后 4 字节是 FCS」
PMA/PMD 不感知 FCS

GMII 上的「帧结束」靠 TX_EN/RX_DV 撤销，不靠某个特殊 FCS 编码。线路上的 /T/R/… 是 PCS 包尾，不是 CRC。

为什么前导码可以被删减

10 Mb/s 时代，前导码主要给对端模拟电路锁时钟。1000BASE-X 改由连续 8B/10B（尤其是帧间 /I/）恢复时钟，目的地 MAC 只要看到完整 SFD 就能解释后面的 DA。因此源 GMII 到目的 GMII 之间允许缩短前导码，极端情况是接收侧 RX_DV 直接从 SFD 开始、前面一个前导码字节都没有。这不一定每种 PHY 都会发生，但 MAC/RS 必须按这个最小值设计。

各层会「吃掉」开头字节的常见原因：

  1. PCS 要等当前有序集发完再发 /S/。TX_EN 往往落在某个 /I/ 或 /C/ 中间，对齐期间已经出现在 TX GMII 上的前导码不会原样上线路。
  2. /S/ 本身占掉 1 个前导码位置。发送用 /K27.7/ 换掉当前字节，接收再还原成 01010101，不保证 7 字节原数到达。
  3. PMA 重对齐最多丢掉 4 个码组。包头更容易碰上尚未对齐，被滑掉的常常是前导码而不是 DA/FCS。
  4. 收钟锁定会拉长 RX_CLK。CRS 到 RX_DV 之间 PHY 可以拉住时钟，这段时间不往 GMII 吐前导码。
  5. 中继器或弹性缓冲增删 /I2/，包起始若落在调整窗口附近，目的侧前导码也会变短。

不能删的是 SFD 和其后的 DA…FCS。 前导码没有载荷语义；FCS 仍从 DA 算到数据末，与前面少了几个 10101010 无关。

接收侧如何从帧里拆出报文

在 RX_CLK 上升沿采样 RXD/RX_DV/RX_ER，还原数据、数据有效、载波和冲突。

GMII 现象 解析给 MAC 的结果
RX_DV=1 且 RX_ER=0 有效报文八位组；RX_DV 最迟须覆盖到完整 SFD
RX_DV 下降 接收帧结束
RX_DV=1 且 RX_ER=1 帧内错误；RS 必须让 MAC 看到 FrameCheckError
RX_DV=0、RX_ER=1、RXD=0x0F / 0x1F 延长 / 延长错误
RXD=0x0E 假载波，不当业务帧
RXD=0x01 正在收 LPI；对 MAC 仍指示 IDLE

半双工不必把 TXD 回送到 RXD；全双工除非寄存器 0.14 回环，禁止自发回环。

PLS 与 GMII 的对应关系：

PLS 原语 GMII 信号 方向
PLS_DATA.request TXD、TX_EN、TX_ER、GTX_CLK MAC → RS → PHY（成帧）
PLS_DATA.indication RXD、RX_DV、RX_ER、RX_CLK PHY → RS → MAC（解析）
PLS_CARRIER.indication CRS PHY → RS → MAC
PLS_SIGNAL.indication COL PHY → RS → MAC
PLS_DATA_VALID.indication RX_DV、RX_ER、RXD RX_DV=1，或延长/延长错误时为有效

信号、时钟与电气

方向 信号 驱动方 作用

发送 TXD[7:0]、TX_EN、TX_ER RS/MAC 成帧后的数据与控制
接收 RX_CLK PHY 合格时 125 MHz ±0.01%；RS 上升沿采样
接收 RXD[7:0]、RX_DV、RX_ER PHY 待解析的数据与控制

RX_CLK 与 GTX_CLK 没有保证的相位关系。失锁时改用标称时钟；切换只允许在 RX_DV=RX_ER=0 时进行。

交流（表 35-8）：GTX_CLK 周期 7.50–8.50 ns，RX_CLK 最小周期 7.50 ns，高/低电平各 ≥2.50 ns，边沿 ≤1.00 ns，VIL_AC ≤ 0.70 V，VIH_AC ≥ 1.90 V，摆率幅值 ≥0.6 V/ns。建立/保持有两套：源端 ≥2.50/0.50 ns，接收器引脚 ≥2.00/0 ns。测量点在接收器输入。

直流（表 35-7）：VOH 2.10–3.60 V，VOL ≤0.50 V，VIH ≥1.70 V，VIL ≤0.90 V。允许驱动器与接收器使用不同电源。

低功耗空闲 LPI

LPI 插在 PLS 与 GMII 之间，EEE 使用 Annex 4A 简化全双工 MAC（带载波推迟）。LP_IDLE.request(ASSERT) 仅当 link_status=OK，且链路变 OK 后至少 1 s 内不得 ASSERT。退出后须等 Tw_sys_tx（1000BASE-T 最小 16.5 µs，1000BASE-KX 最小 13.26 µs）。发送进入 LPI 至少 9 拍后才可停 GTX_CLK；接收撤销 LPI 前必须先恢复 RX_CLK 并至少产生一个上升沿。

PCS：从 GMII 字节到线路码组

PCS 把已经成帧的八位组流变成介质上可连续跑的 10-bit 码组；接收时再拆回 GMII，给 RS 解析。客户是经 RS 的 MAC，也可以是中继器。1000BASE-X 的 PCS/PMA 改编自 Fibre Channel 的 8B/10B，目标 BER 为 $10^{-12}$。GMII 与 TBI 都是可选物理实例，片内可以不引出。

可观察口宽度有硬约束：GMII 必须八位组宽，TBI 必须 10 bit，MDI 必须串行。

五个过程怎么配合

  1. Transmit：看 GMII 与 xmit。CONFIGURATION 发 /C/，IDLE 发 /I/，DATA 才在空闲里穿插包。同时用「正在发且正在收」产生 COL。
  2. Receive：把同步后的码组译成 GMII 信号；xmit≠DATA 时把 /C/、/I/ 和配置字交给自动协商。
  3. Carrier Sense：非中继器在发送或接收为真时开 CRS；中继器只看接收。
  4. Synchronization：判定码组是否对齐，输出 sync_status。
  5. Auto-Negotiation：Clause 37。1000BASE-KX 改走 Clause 73。

8B/10B 和运行差分

数据编成 D 码组 /Dx.y/，控制编成 K 码组 或有序集。线路上 tx_code-group[0] 先出。每个符号 3–8 次跳变，用来恢复时钟并限制连码。

Running Disparity（RD） 只有正、负两态。发送上电从负开始；接收可任选。每个八位组有 RD−/RD+ 两列编码。RD 按子块算：abcdei 与 fghj。1 多于 0（或特定中性块）则结束为正。接收只在当前 RD 那一列查找，找不到即无效，但仍用该码组更新 RD——所以「这一拍才无效」可能是更早的错误破坏了差分。

多码组有序集的首码组必须落在偶编号位置。comma+ 为 0011111，comma- 为 1100000。

常用有序集：

名称 编码 作用
/C1/ /C2/ /K28.5/D21.5/ 或 /D2.2/ + Config_Reg 自动协商
/I1/ /I2/ /K28.5/D5.6/、/K28.5/D16.2/ 空闲；/I1/ 把 RD 拉回负
/S/ /K27.7/ 包起始，接收时还原为 01010101
/T/ /R/ /K29.7/ /K23.7/ 包结束、延长、偶边界填充
/V/ /K30.7/ 错误传播
/LI1/ /LI2/ /K28.5/D6.5/、/K28.5/D26.4/ LPI

发送：先定有序集，再定 10 bit

有序集状态机（图 36-5）决定下一拍发哪一类符号，码组状态机（图 36-6）再按奇偶和 RD 选出具体 10 bit。

状态 大致动作
CONFIGURATION 发 /C/
IDLE 发 /I/
START_OF_PACKET 发 /S/，COL=receiving
TX_DATA 发 /D/
TX_DATA_ERROR 发 /V/
END_OF_PACKET_* 发 /T/，必要时再 /R/ 对齐偶边界
CARRIER_EXTEND 先 /T/（约两拍），再每拍 /R/

TX_EN 新置位时，等当前有序集结束再用 /S/ 替换那一拍前导码。单包或突发首包的 /S/ 跟在 /I/ 后，突发后续包跟在 /R/ 后。

接收：先分协商区，再拆数据包

sync_status=FAIL 时进入 LINK_FAILED，不把未对齐符号当业务帧。

协商/空闲区认 /K28.5/：下一码是 /D21.5/ 或 /D2.2/ 就收配置字，否则当 IDLE。xmit=DATA 且载波不是 /S/，判假载波（RXD=0x0E）。

数据包区见到 /S/ 后：

  1. RX_DV=1，把 /S/ 换成 01010101。
  2. 后续合法 /D/ 译到 RXD；非法则 RX_ER=1。
  3. check_end 看包尾：/T/R/R/ 或 /T/R/K28.5/ 正常结束；/R/R/S/ 是突发下一包。

CRS 在 receiving=1，或非中继器且 transmitting=1 时置位。COL 在包内及延长期等于当前 receiving。

同步时，Rx 会不会冻住奇偶和 RD

不会。未锁定时接收端并不维持一套「等合适码流再动」的奇偶和正负。

量 未锁（LOSS_OF_SYNC） 锁上之后
码组边界 未知，窗口可能切错 comma 在最左，有序集从偶位置开始
rx_even 尚未建立。第三个最左 comma 时 强制为 TRUE，不沿用旧值 每码翻转
RD 上电任选正或负；之后每个 10-bit 窗口都更新，无效也更新 继续按对齐码组更新；/I1/ 纠回负

未对齐时这些 RD/无效判决没有链路含义，也不能交给 MAC。失锁再锁是重新标定奇偶，不是保持旧状态。sync_status=FAIL 持续 10 ms 后会启动自动协商并发送 /C/。PMA 见到 comma+ 可重对齐，最多增删 4 个码组。

PMA 衔接

PCS 以 125 MHz 把 10-bit 码组交给 PMA；PMA 串行化，bit 0 先出，线上 1.25 Gb/s。固有延迟至少 10 bit time。可选 TBI 用 PMA_TX_CLK 和一对 62.5 MHz 相差 180° 的接收钟。

自动协商：在 PCS 里，不走 GMII 数据脚

1000BASE-X 自动协商位于 PCS 内，用 /C/ 与 /I/ 在 介质上交换能力，不经过 GMII 数据总线。协商完成不等于光功率或 BER 合格。对等、无主从。进入或退出都可能短暂丢帧。1000BASE-KX 改走 Clause 73。

本端可以少广告自己有的能力，但不得广告没有的能力。

和 PCS 怎么交接

link_timer 标称 10 ms（+10 ms / −0 s）。匹配函数由码流连续计算：

  • ability_match：连续三个 Config（忽略 Ack）相同
  • acknowledge_match：连续三个相同且 Ack=1
  • consistency_match：两者对应的值一致，否则必须重启
  • idle_match：连续三个 /I/

状态机怎么走完

实现上记住五条：重启页必须先发全 0；Ack 至少三个连续匹配页之后才置；一致性失败不得完成；重新协商会丢帧；想固定某模式时，建议仍开协商、只广告该模式。

Base Page 和寄存器

双工解析：全双工优先于半双工。PAUSE 按双方 PAUSE/ASM_DIR 组合成只关、只发、只收或对称收发。远端故障：00 正常，01 Offline，10 Link_Failure，11 协商错误。

常用管理寄存器：0（使能/重启/回环）、1（完成、Fault、link）、4/5（本端/对端 Base Page）、6（Page Received）、7/8（Next Page）。

时延与排障顺序

半双工要保证能看到冲突；全双工主要保证 PAUSE 可预期。

场景 上限
GMII TX_EN=1 采样至 MDI 输出 136 bit
半双工：MDI → CRS/COL 置位或撤销 各 192 bit
全双工：MDI → RX_DV 撤销 192 bit
半双工 DTE：MAC 发送开始 → MDI 184 bit
半双工 DTE：MDI → 冲突检测 240 bit

建议按层排查：PMD 是否可见 → PMA 是否锁定 comma → PCS 同步与无效码组 → /C/ 和寄存器核对协商 → GMII 成帧/解析边沿 → 最后才查 MAC FCS 和队列。底层未同步时，上层抓包「没有帧」是症状，不是根因。

实现时要注意什么

逻辑上：

  • RS 两侧都要做：发送从预导码装到 FCS，接收按 SFD 拆开，错误路径能迫使 FrameCheckError。
  • RX_CLK 与 GTX_CLK 分域，不要假设同相。
  • 接收须容忍「只有 SFD、无前导码字节」。
  • PCS 不是一张 8B/10B 查找表，要有发送/接收/同步状态机和 xmit 门控。
  • xmit 未到 DATA 时，业务帧不上介质，/C/ 也不当业务帧交给 MAC。
  • 同步丢失 ≥10 ms 必须进入 /C/；consistency_match 失败必须重启协商。

硬件上：在接收器输入点测直流/交流和两套建立保持；覆盖最短前导码、假载波、延长、突发、冲突、LPI 和协商重启。不用单一 link up 代替误码和光电预算。

常见问题

Q：GMII 是不是就是 RGMII，或者就是网线上跑的协议？
A：都不是。GMII 是 8 位、125 MHz 的 MAC–PHY 并行接口。RGMII 用双沿减脚，时序不同。网线/光纤侧由 PCS/PMA/PMD 处理。

Q：125 MHz 是不是只能跑 125 Mb/s？
A：每时钟传 8 bit，线速是 1 Gb/s。8B/10B 之后线路是 1.25 Gb/s。

Q：RS 是不是只负责把 GMII 信号翻译给 MAC？
A：不是。它既要把 MAC 报文/指令打成 GMII 帧，也要从 GMII 帧拆回报文和指示。

Q：FCS 是谁算的？PCS 会检查 CRC 吗？
A：MAC 算、MAC 查。PCS 把 FCS 当普通数据码组；RS 只在出错时保证 MAC 最终校验失败。

Q：为什么接收到的前导码比发送的短？
A：千兆不再靠前导码锁钟。PCS 等有序集对齐、/S/ 替换、PMA 滑码、收钟拉长，都会吃掉开头的 10101010。只要 SFD 完整即可。

Q：PCS 同步完成前，接收端会保持自己的奇偶和 RD 不变吗？
A：不会冻住。未锁定时窗口可能切错，RD 仍按每个 10-bit 窗口更新；奇偶在第三个最左 comma 时被强制标成偶，不沿用失锁前的值。

Q：自动协商完成是不是就说明光纤/线缆没问题？
A：不是。/C/ 只交换能力，不测光功率和 BER。协商也不走 GMII 数据脚。

Q：全双工能不能拿 CRS/COL 当控制？
A：标准未规定全双工下它们的行为，不能当收发依据。半双工不必、全双工禁止自发把发送回环到接收（除非 0.14）。

总结

读完可以按这条线把实现串起来：

  1. 千兆链路是分层双向管道，不是单向数据泵。
  2. RS 在 MAC 原语与 GMII 之间成帧和解析；FCS 由 MAC 计算，前导码允许被 PHY 缩短。
  3. PCS 用状态机区分协商、空闲和业务，再用 8B/10B 送到 1.25 Gb/s 串行线路。
  4. 同步完成前，Rx 的奇偶由 comma 重新标定，RD 持续按窗口更新，二者都不会「冻住等好码」。
  5. 自动协商在 PCS 内用 /C/ 走完重启 → 能力 → Ack → 空闲 → LINK_OK 后，才允许 xmit=DATA。

正确实现要让每一层的帧界、指令、码组、时钟、协商和时延对齐，而不是只让 TXD/RXD 跑到 125 MHz。设计与合规测试以完整、已授权的 IEEE 802.3 原文和器件手册为准。
